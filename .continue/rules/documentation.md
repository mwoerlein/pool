# Documentation Standards

When updating or creating project documentation under `.continue/`:
1. **Language**: All documentation files must be written in **English**.
2. **Style**: Keep information **compact, abstract, and generally valid** (focus on core architectural decisions, recurring patterns, and best practices rather than temporary or overly specific implementation trivia).

## Project Masterplans & Roadmaps
- **Purpose**: Project files under `.continue/projects/` serve as high-level roadmaps and architectural specifications for specific features or initiatives.
- **Design Principle**: They focus on overarching goals and milestones while linking to central rules and architecture docs under `.continue/rules/` rather than duplicating them.

## Code Examples & References
- **Fictional Names**: Always use generic, fictional names and classes in documentation code snippets.
- **Referencing over Duplication**: Rely on clean referencing rather than redundant copying across files to prevent architectural drift.
